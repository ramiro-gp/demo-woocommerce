# H10 — Auditoría de dependencias de identidad

Inspección estática de theme, cinco plugins propios, configuración, bloques, patrones, fixtures, scripts y herramientas locales. Esta tabla identifica dependencias por familia y evita reemplazos indiscriminados. El resultado ejecutado y la evidencia de ambas tiendas se registran en [H10](h10-rebranding-portability.md).

Clasificación: **DEMO válida** = contenido o herramienta explícitamente perteneciente a TRAMA; **editable** = configuración o contenido particular de cada comercio; **accidental** = supuesto de la DEMO en presentación/código que debe generalizarse; **funcional** = comportamiento compartido que no debe derivar de una marca. Los nombres internos históricos no son por sí mismos filtraciones de identidad.

## Búsquedas y límites

Se buscaron `TRAMA`, `pa_talle`, `pa_color`, `talle`, `localhost`, remitentes `.test`, nombres de productos/medios, opciones nativas, IDs, slugs y configuración en las áreas anteriores. Un comentario CSS “TRAMA checkout” no cambia datos/función; se clasifica como referencia histórica, no como una dependencia comercial ejecutable. Las claves de ownership `trama_h*` en herramientas históricas protegen datos y no deben cambiarse de manera indiscriminada.

La configuración almacenada de cada instalación también necesita inspección de base y navegador: una búsqueda de archivos no prueba ausencia de contaminación en menús, contenido, emails, medios o metadatos. Esas comprobaciones y las correcciones finales están en el informe H10. La auditoría no aprueba Mercado Pago ni las condiciones productivas; conserva los bloqueos de [H9](h9-production-readiness.md).
